# #1039 步驟 0：延後測試能改寫成「對答案目標」的比例（2026-11-22）

結論：設計 v3 有一個未決問題：`probe` 能不能執行子程序，並把標準輸出或寫出的檔案內容當觀察值。在它定案前，這份樣本的 31 個測試 commit 只有 1 個（3%）能確定整個改寫成對答案目標，所以步驟 2 先不開工。若定案為可以，最多 16 個（52%）可能可以，但要用同一份樣本重算才算數。
- 設計沒有寫數字門檻（「太少」沒有定義），停或繼續由 layer1 決定；layer1 已選擇先定案再重算（見「下一步」）。
- 能確定寫不出來的測試占 24%，主要是函式替身。

設計：#1039 設計 v3（issuecomment-7073287663）。本報告只做計數，不含程式。

## 樣本
- 來源：Cairnwork 在一個內部工具 repo 上的 31 次實跑，每次一個測試 commit。31 個全部取回，0 個取不到。
- 單位：新增或改動的測試函式共 196 個。Python 檔以 AST 列出；兩支 shell 腳本測試各算 1 個。
- 方法：靜態閱讀判斷，沒有在 base 上執行。「base 上有牙齒」是估計。

## 分類規則（設計 v3）
- **A**：能寫成 probe，至少有一個強鍵，而且估計 base 上該強鍵的值不同或不存在。
- **B**：能寫成 probe，但只有弱鍵（bool、None、[-16, 16] 的整數、最多一個字元的字串、空容器、`observe_raises`）。
- **C**：有強鍵，但強鍵在 base 上相同（沒有牙齒）。
- **P（子程序觀察未定）**：要執行 CLI、腳本或假的外部程式，才看得到結果（結束碼、標準輸出、寫出的檔案）。這一類取決於上面那個未決問題，不算進「寫不出來」。判定方式是機械式的：分類紀錄的原因欄提到子程序、CLI、腳本、shell 或假程式，就歸這一類。
- **D（寫不出來）**：不靠 pytest 的機制就寫不出來。
  - 函式替身一律算 D：`monkeypatch`、`mock.patch` 或任何替換模組函式與屬性的寫法都算。probe 沒有 pytest，替身要手寫，而手寫等於改變被測程式。
  - 只在 `setUp` 手動設定模組變數、不替換函式的測試，算可以寫成 probe。
- **E**：取不到或判斷不了。

## 結果

| 類別 | 測試函式 | 比例 |
|---|---|---|
| A 強鍵、估計有牙齒 | 21 | 11% |
| B 只有弱鍵（拒收） | 21 | 11% |
| C 強鍵沒有牙齒（拒收） | 1 | 0.5% |
| P 子程序觀察未定 | 106 | 54% |
| D 寫不出來 | 47 | 24% |
| E 取不到或不清楚 | 0 | 0% |

D 的原因：
- 函式替身：41；
- 孤兒子程序是否存活（kill 與 pid 檔）：5；
- 牆鐘時間：1。

commit 層級（31 個）：
- 新增或改動的測試全部在 A（現在就能整個改寫）：**1（3%）**；
- 只有 A 與 P、至少一個 P（定案後才可能改寫）：15；
- 至少有一個 D：12；
- 至少有一個 B 或 C：7；
- 至少有一個 A：10；
- 只有 P：13。

## 讀法與限制
- **「最多 16 個」是上限**：P 類定案為可以觀察後，每個測試還要有強鍵、在 base 上有牙齒才算 A。有些只看結束碼或「有沒有寄信」的測試會落到 B。
- **B 拒收的 21 個中，12 個其實有自然的強觀察值**（比對到的文字、回傳的 dict 或 list），只是原測試只斷言了 bool 或長度。人改寫時多半能補上強鍵，所以 B 的拒收率高估了實際損失。
- **A 的 21 個中，15 個呼叫的是這次才新增的函式**，「base 上不存在」就算有牙齒。真正比較既有行為差異的只有 6 個，其中 1 個信心低，可能屬 C。
- **樣本偏差**：來源只有一個以 CLI、排程與檔案為主的工具 repo，P 與 D 都會偏高；函式庫型的 repo 比例可能較好。大 commit 主導函式層級的計數（最大的幾個分別加了 23、17、14 個測試）。
