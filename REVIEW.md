# Reviewing Cairnwork PRs

For every reviewer (Claude, Codex, Gemini or human). `AGENTS.md` owns the process (rounds, records, risk tiers); this file says what to look for and how to report it.

## What counts as broken

Tag these `[introduced]` when the PR causes them; they block the merge.

- A failure in a safeguard, in verification or in a Core call ends in a success state or an unauthorised side effect.
- A task is marked complete without a nexus-core VERIFIED verdict, or a task gets a second owner.
- A doc lies: `README.md`, `docs/`, `AGENTS.md`, a docstring, CLI help or the PR body says the code does something it does not do, or no longer does. Docs count as code here.
- A config points the wrong way: a workflow, `pyproject.toml`, ruff, pytest or pyright setting, script default or environment variable that sends work to the wrong path, branch, account, model or check, or that silently skips tests (skipped sandbox tests count).
- A test still passes with the change reverted or with a wrong implementation.
- A CI limit breaks: file ≤400 lines, function ≤80 lines, `cairnwork_sandbox` ≤1,200 lines, import cycles, core importing `experimental`.

Style, naming and "could be cleaner" are `[nit]` and never block.

## What you do not need to read line by line

- `uv.lock`: generated by uv. Check that it changed only together with `pyproject.toml` and that every added or changed package (name, version, source) is intended; CI's `uv sync --locked` checks only that the two files agree.
- `docs/drills/*.json`: run records written by the drill scripts. For a new record, check only that `docs/DRILLS.md` describes it truthfully. An edit to an existing record changes past evidence: ask why.
- `experimental/*/OWNER` and `experimental/*/EXPIRES`: check only that an owner is named and the expiry is at most 14 days after the PR.

## How to report

- Every finding gives `file:line` at the reviewed head and one sentence on what goes wrong. A finding without `file:line` is not a finding; for something missing, name the file (or the PR body) where it belongs.
- Tag each finding `[introduced]` (this PR caused it; blocks), `[pre-existing]` (already on main; goes to an Issue) or `[nit]`.
- From round 2, say for each earlier finding whether its whole class is gone, not only the cited line.
- End with one plain line: `N issues (M introduced)`, or `No issues found.` Do not end on "looks mostly fine".

## How we judge review quality

Not by rounds or comment counts, but by the share of merged PRs that later need a fix-up Issue for a defect the review should have caught. Cairnwork fixes forward instead of reverting (main had 212 commits and 0 reverts as of baf92db, 2026-10-28), so revert counts say little here; fix-up Issues are the signal.
