# committed_sys_path (Cairnwork Experimental Capability)

## Threat Model
In Cairnwork candidate validation, malicious or flawed patches may alter Python module resolution to hijack imports during verification. Write-side deny-lists alone fail to converge as candidates adopt indirect file-writing primitives (`builtins.open`, `functools.partial`, container lookups `[open][0]`, compression writers, or shell redirects).

`committed_sys_path` checks the search-path resolution side of in-process Python edits: any new or modified in-process search-path modification introduced by a candidate commit must statically resolve to a base-committed repository directory that is not contaminated by candidate-introduced shadow modules, and must not reach `sys` or `sys.path` through unrecognized dynamic aliases or reflection escapes.

## How It Works
- **Search-Path Edit Detection (`path_edits.py`)**: Detects additions and modifications to `sys.path` (`.insert()`, `.append()`, `.extend()`, slice/index assignment, `+=`, `del`, `list.insert(sys.path, ...)`), `site.addsitedir(...)`, `__path__`, `submodule_search_locations`, `monkeypatch.syspath_prepend`, and `pytester.syspathinsert`. Unchanged search-path edits in modified files are subtracted via semantic key diffing (`diff_path_edits`), unless the resolved target directory becomes shadow-contaminated.
- **Positive-Rule `sys` / `sys.path` Tracking & Escape Guards (`aliases.py`, `sys_guard.py`, `reflection_guard.py`)**:
  - Enforces positive rules on every `sys` and `sys.path` expression: only recognized read-only inspections (`len(sys.path)`, `sys.path[i]`, `sys.path[:]`, `sys.path.copy()`, iteration/membership, safe `sys.<attr>` loads), safe writable `sys` config attributes (`argv`, `dont_write_bytecode`, `stdout`, `stderr`, `ps1`, `ps2`, `tracebacklimit`), handled path edits, and direct local aliases (`s = sys`, `p = sys.path`, excluding `ClassDef` attributes) are accepted. Passing `sys` or `sys.path` to unknown functions, containers, lambdas, context managers, class attributes, or unknown operations rejects (`sys_escape` / `sys_path_escape`).
  - Blocks reflection, scope-dict, and dynamic import escapes targeting `sys`, `sys.path`, or import helpers: `__import__`, `importlib.import_module` (for sensitive or dynamic module names), `globals()` / `locals()` / `vars()` / `__dict__` escapes, `getattr` / `setattr` / `delattr` / `attrgetter` / `methodcaller` on tracked sensitive objects or sensitive escape attributes, `sys.modules['sys']` / `sys.modules.get('sys')` (including aliases and dynamic subscripts), `__getattribute__` / `__setattr__`, and syntactic `eval` / `exec` / `compile`.
- **Component-Stack Path Evaluator (`evaluator.py`)**: Evaluates `__file__`-anchored path expressions (`os.path.dirname`, `abspath`, `realpath`, `join`, `os.fspath`, `pathlib.Path` / `PurePath` / `PurePosixPath`, `.resolve()`, `.absolute()`, `.parent`, `.parents[k]`, `/`, `.joinpath()`, `str()`, and unique-binding constants). Bare non-`__file__`-anchored relative strings (e.g. `""`, `"."`, `"bin"`), absolute/home/Windows/UNC paths, rebound `__file__` or `str`, literal `_CW_ROOT_` segments, `..` after descending into a subdirectory (`descended` guard), and paths traversing non-existent or symlinked directories in either base or candidate git trees (`visited_dirs` against `load_tree_dirs`) are rejected (`NON_COMMITTED_SEARCH_PATH`).
- **Shadow-Directory Model (`git_io.py`, `source_check.py`)**:
  - `check_source(...)`: evaluates against caller-supplied `committed_dirs` and `shadow_dirs`; clean committed targets such as `dirname(realpath(__file__))` or `../bin` return `ACCEPT` when not in `shadow_dirs`.
  - `check_commit(...)`: computes `shadow_dirs` and `cross_shadow_dirs` from the candidate commit diff against base:
    - `shadow_dirs`: directories where the candidate added/modified binary/hook shadows (`.pyc`, `.pyo`, `.so`, `.pyd`, `.dylib`, `.pth`, walking up `__pycache__` and `__init__.py` packages), or added `.py` modules/subpackages whose top-level exposed name collides with Python stdlib, protected modules (`pytest`, `cairnwork`, etc.), base module stems, or base imports. Any search-path target resolving into `shadow_dirs` — including unchanged redirects in untouched candidate `.py` files (`scan_unchanged_shadows`) — is rejected (`SHADOW_IN_COMMITTED_DIR`).
    - `cross_shadow_dirs`: directories where the candidate added new non-conflicting `.py` modules. Search-path edits from a different caller directory (`norm_dir != caller_dir`) into `cross_shadow_dirs` reject (`SHADOW_IN_COMMITTED_DIR`), whereas same-directory clean sibling helpers (e.g. `bin/issue_flow.py` adding `dirname(realpath(__file__))` next to a newly added non-conflicting `bin/procgroup.py`) return `ACCEPT`.
- **Bounded AST & Error Propagation (`__init__.py`, `source_check.py`, `git_io.py`)**: Enforces bounded AST depth (`_MAX_AST_DEPTH = 500`) and catches `SyntaxError`, `ValueError`, `UnicodeDecodeError`, `TypeError`, `RecursionError`, and `MemoryError` as `ERROR UNREADABLE_SOURCE`. Rejects git option-injection refs (`-x`, `--help`, empty refs) and invalid commits as `ERROR INVALID_COMMIT`, and git diff/tree/blob failures as `ERROR GIT_ERROR`. Any `ERROR` in `check_commit` aborts the run and returns `ERROR` immediately.

## Activation
This module is experimental and **disabled by default**. To enable CLI execution:
```bash
export CAIRNWORK_EXPERIMENTAL_COMMITTED_SYS_PATH=1
```
Without this variable set, invoking the CLI exits immediately with code 2. Optional CLI flags: `--include-tests` (include top-level `tests/` and `conftest.py`) and `--allowlist-prefix <prefix>` (segment-aligned prefix exclusion).

## Known Limitations
- **Top-level `tests/` and root `conftest.py` skipped by default**: `include_tests` defaults to `False`, so top-level `tests/**` and root `conftest.py` return `ACCEPT SKIPPED_TEST_FILE` unless `--include-tests` / `include_tests=True` is passed. (`src/**/test_*.py`, `src/tests/**`, and lookalike prefixes such as `tests_evil/` are still checked.)
- **`eval` / `exec` and indirect code execution**: Syntactic `eval(...)`, `exec(...)`, and `compile(...)` calls are rejected, whereas arbitrary runtime code execution outside blocked syntactic primitives (e.g. native extensions, C-level hooks, or pre-compiled code objects without blocked calls) is outside static AST analysis.
- **Import machinery, dynamic loaders, `PYTHONPATH`, and runtime `.py`/`.pth` writes (`#1198`)**: `sys.meta_path`, `sys.path_hooks`, `sys.path_importer_cache`, and `sys.modules` are enforced via positive read-only allowlists; `importlib` dynamic loaders/`FileFinder`/`PathFinder`/`reload`/`runpy` are blocked (allowing `FileFinder.path_hook(...).__code__` and non-call references); `os.environ`/`putenv`/`subprocess(..., env=...)` `PYTHONPATH` injections are verified via `StaticPathEvaluator`; and runtime `.pth`/`.py`/binary writes are blocked.
- **Non-`.py` configuration files**: Non-`.py` configuration files (`pytest.ini`, `pyproject.toml`, `.env`) are outside static Python AST analysis.
- **Cross-file unchanged redirect residual**: `scan_unchanged_shadows` checks unchanged candidate `.py` files containing `_UNCHANGED_PREFILTER` tokens against candidate-introduced `shadow_dirs` / `cross_shadow_dirs`, but skips unchanged files that fail to parse (`tree is None`) and cannot detect runtime writes or non-file-addition side effects targeting an unchanged redirect's directory.
- **Whole-range `ERROR UNREADABLE_SOURCE` on unparseable non-test `.py`**: Any changed non-test `.py` file that fails UTF-8 decoding, Python parsing, or exceeds `_MAX_AST_DEPTH = 500` causes `check_commit` to abort the entire commit range with `ERROR UNREADABLE_SOURCE`.
- **No blackbox trust guarantee**: This module is an experimental static AST safeguard, not a sandbox or blackbox isolation boundary.
